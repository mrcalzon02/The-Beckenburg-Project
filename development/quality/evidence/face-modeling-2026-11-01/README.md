# Actual native face modeling and publication

The three PNGs are real Swing fixture UI captures: native working geometry at left, an explicitly uncommitted native-schema candidate at right, and the final committed model. They are not production model art, installed gameplay or complete G2 acceptance.

The human test selects the real face by mouse, cancels pending/completed previews, invalidates changed parameters and stale native revisions, applies extrude/inset, undoes/redoes, saves/reopens and publishes through the actual runtime asset registry. Every actual game GLB corner, UV and winding is compared with committed native data; exact source and native archive bytes are checked.

The publication negative control compiles exact AssetImportDialog source4be25e3a ahead of the current native project/test classpath. It performs a real native edit after review and demonstrates runtime X=0.0 while native X=-0.25. The corrected path refuses before any native save/archive, then an actual human review refresh publishes coherent native/runtime data.

Face operations currently edit one triangulated native face, require oriented manifold input, and retain its ID/part. Extrude accepts signed normal distance; inset accepts a fraction between0 and1, preserving planar UV interpolation. Both add3 vertices and6 triangles. Geometric self-intersection repair, region modeling, bevel/slide, full normals/material interchange and later gates remain open. No agent/MCP modeling interface is admitted.
