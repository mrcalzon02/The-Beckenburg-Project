# Indexed mesh authoring checkpoint

The existing **IMPORT MODEL** dock now owns an `EditorTopologyProject` for OBJ/STL and native `.btop` sources. The working mesh is authoritative: adjacency, wireframe/reduction preview and published GLB triangles derive from its stable indexed vertices, face IDs, named parts and per-corner UVs. This is a human authoring workflow, not an agent scene or a second game renderer.

## Working operations

- Choose a source, select its vertex ID and edit X/Y/Z, then press **MOVE VERTEX**. The selected actual vertex is highlighted in the working viewport. A move that introduces a degenerate face is refused.
- **UNDO MESH / REDO MESH** use the portable `EditorHistory` against this same project. Moving distinct vertices onto coincident positions does not weld their IDs or face connectivity.
- **SAVE MESH** writes a versioned native `.btop` document under the editor topology directory; its actual path is reported and available on the Save button tooltip. **REOPEN MESH** is undoable. The source chooser also opens saved `.btop` documents in fresh projects.
- Native saves enforce the shared8MiB output budget, staged readback, journal recovery, distinct prior version and cooperative writer lock. An observed disk SHA is checked inside the lock **after staging**; another editor's newer save or external deletion cannot be overwritten by a stale project. Explicit reopen observes that actual newer revision. Unknown schema versions and foreign-source backups fail without replacing live state.
- **PUBLISH TO EDITOR** validates the reviewed source fingerprint, saves/archives the exact edited `.btop` authoring document, and publishes through the existing GLB writer, native game decoder and imported asset registry. Original input and editable authoring bytes have separate SHA metadata beside the generated runtime GLB. Source changes after review refuse publication; raw GLB level0 cannot bypass this check by rereading unobserved data.
- GLB source vertex editing is explicitly unavailable while the current regeneration path cannot retain its original material/normal bindings. Unmodified GLB publication retains exact reviewed bytes. Nonzero GLB reductions are blocked in both the human dock and native publisher until source material/UV bindings can be preserved.

The `.btop` v1 schema stores owning project ID, original-source fingerprint, source name/size, stable vertices, stable faces, part ownership and corner UVs. Double-precision authoring values remain native; game GLB output uses the existing float buffers. Metadata and counts are bounded. Native schema v1 currently rejects future versions rather than inventing a migration. Original OBJ/STL bytes are retained even after edits; native documents are intentionally editable and retain their previous distinct save.

Conditional disk revisions are now also adopted in native mission/Castle adapters; broader migration/adoption and later modeling gates remain separate.

## Parametric primitive checkpoint

**NEW MESH** creates a real empty native document. Choose box, plane, cylinder, sphere or torus; set width/height/depth and bounded segments/rings (rings is the box/plane grid subdivision count), then **PREVIEW PRIMITIVE**. The right panel shows an uncommitted primitive. Parameter changes invalidate that review. **APPLY PRIMITIVE** appends one separately owned part through the same native project/history; existing vertex/face IDs and corner UVs remain unchanged. Undo, redo, native save/reopen and ordinary runtime publication apply to this geometry. Primitives are centered at the origin, Y up; overlapping parts are deliberately separate until explicit modeling operations exist. Torus tube proportions are fixed; dimensions scale its envelope. This checkpoint does not persist an editable modifier stack.

`EditorMeshPrimitivesTest` checks all five generators for deterministic output, outward triangle winding, Euler topology, exact plane boundaries, closed shells, corner UV bounds, maximum subdivisions under 256 MiB, stable append IDs, transactional undo/redo and native roundtrip. The actual human dock test creates all five with real buttons, rejects stale parameter reviews, and compares every published position/UV/winding through `GlbProps.model`. The captured fixture UI is advisory evidence; full textured material/normal interchange and the G2 exit remain open. No primitive operations have been added to the agent interface.

## Global move gizmos

Select a vertex, edge or face, then drag a colored X/Y/Z endpoint in the working viewport. The pivot is the selected vertex or the mean of the selected edge/face vertices. Axes perpendicular to an orthographic view have no draggable projection. Movement uses world coordinates and the **Move grid** distance (0 disables snapping). During dragging, a marker previews the projected target and native geometry/history stay unchanged. Release commits one validated native translation; Escape/right-click cancels. A native revision change during the drag refuses the stale release. One undo/redo restores the entire selected set. Degenerating, unknown-ID and nonfinite changes are refused atomically; connectivity, corner UVs and existing IDs remain native.

The real dock test drives all three selection modes with mouse press/drag/release, proves only the selected IDs moved on global X, checks grid increments, exact one-step undo/redo, unchanged state/history after Escape and every transformed GLB corner in the real decoder. Portable native tests cover whole-mesh translation, subset-degeneracy rejection and transformed save/reopen. Gizmos currently translate on global axes; rotation/scale, local/normal coordinates, arbitrary pivots, multi-selection and modeling operations remain open.

## Visible and X-ray area selection

Enable **AREA SELECT**, choose BOX or LASSO, and drag in the working viewport. With X-ray off, actual nearest native triangles determine visibility of each candidate vertex. X-ray includes the hidden IDs too. Lassos use polygon inclusion rather than their bounding rectangle, including concave regions and boundaries; collinear/short or oversized paths are refused. Selection runs in a bounded background query over an immutable projection index of the actual native snapshot. It never edits or substitutes scene data. Escape cancels a pending result; changed native project/revision refuses stale selection. A five-million geometric-test budget refuses overly dense work atomically, retaining the prior selection.

Selected vertices share the native centroid move gizmo and one transaction/undo step. Selection itself adds no geometry/history changes. `AssetImportBoxSelectionGuiTest` drives actual visible/X-ray rectangles and lassos against two overlapping native triangle layers, tests cancellation/stale revision refusal, moves the selected group and compares every corner through the real game decoder. `EditorMeshPickingTest --stress` queries all120000 triangles/360000 vertices under256MiB and also checks bounded dense-overlap refusal. The shared native CI script and standalone stress gate include these cases. Area selections currently replace the vertex selection; additive/subtractive modes and edge/face region or loop/ring selection remain open.

Position/UV declarations and source counts are bounded; optional immutable index metadata keeps the existing unindexed Mesh constructor compatible. Unindexed inputs (including STL) retain per-part geometric connectivity; native working snapshots always retain their explicit stable IDs.

## Reversible face extrude and inset

Select FACE mode and click an actual triangle. Choose EXTRUDE (signed normal distance) or INSET (fraction greater than0 and less than1), then **PREVIEW FACE EDIT**. Working and candidate geometry share bounds. The native project is unchanged during review. **APPLY FACE EDIT** commits exactly that validated native candidate as one history step; parameter changes, Cancel/Escape, stale revisions and foreign owners invalidate it. Re-select a native face after commit. Source vertices and unselected faces keep IDs; the cap retains the selected face ID/part. Extrude preserves cap UVs and generates side UVs; inset interpolates the original planar UV mapping. Oriented manifold open/closed topology and budgets are validated before commit. Self-intersection repair is not claimed.

Pending face previews disable ordinary edit/publish controls. Save/reopen and publication consume committed native data. Publication is bound to an observation of that actual native owner/revision, not the UI mesh cache. A changed source refuses before writes; explicit review observes the new source. Reviewed save/capture is atomic with native edits and returns immutable exact bytes/fingerprint. Later edits remain unsaved, and the native project owns dirty-state tracking. The exact prior UI demonstrated a real native/runtime mismatch; the corrected human test verifies coherence.

`EditorFaceModelingTest`, `AssetImportFaceModelingGuiTest` and `AssetImportPublicationRevisionGuiTest` cover this workflow through the independent JAR, actual buttons/mouse, native persistence/archive and every game-decoder corner. Current operations target a single triangulated face; multi-face regions, weld/repair, bevel/slide, advanced transforms and full material/normal interchange remain open. No mesh operations have been added to the agent interface.

## Explicit weld and degenerate repair

Select vertices (X-ray area selection can include all sides of complete seams), then **PREVIEW WELD COINCIDENT**. Within each part, exact coincident positions share the smallest selected stable ID; corner UVs remain independent, so existing UV seams survive. Affected collapsed triangles are counted and removed in the candidate; unrelated invalid faces are not silently removed. Different parts remain distinct. The operation refuses incomplete seams/point-only contacts or any invalid resulting topology. It does not guess a distance tolerance or repair unrelated source errors.

**PREVIEW REMOVE DEGENERATES** explicitly removes zero/nonfinite-area triangles from the native document, retaining every surviving face/corner and all vertex IDs. Both operations use **APPLY MODEL EDIT / CANCEL MODEL EDIT**, shared history, native save/reopen and ordinary checked runtime publication. Working and candidate geometry are derived from native snapshots; no separate editable scene exists. Current repairs require a valid result; arbitrary distance welding, partial regional repair, orientation fixes and nonmanifold surgery remain open.

`EditorMeshRepairTest --stress` verifies the full120000-face/360000-source-vertex workload under256MiB. `AssetImportMeshRepairGuiTest` drives real area selection/buttons and compares every published native game corner and archived native state. The original source remains unchanged. Full normals/material interchange and the G2 exit remain open.
