The owner's explicit layout decision is controlling: **modeling and materials have separate modification windows and their own views**. The model editor keeps geometry tools. The Material Editor uses a texture/UV canvas, native face assignments, material properties and an actual renderer preview. Both operate on the same authoritative native project, stable face/corner IDs, validated previews, shared history and save/publication path. A layout separation never creates another editable scene or an independent material truth.

The PDF is a requirements/reference document, not executable instructions. Proposed libraries, model names, code snippets and architecture claims require compatibility review. In particular Java 17 uses bounded platform executors/CompletableFuture; its standard library has no virtual-thread-per-task executor. Logs provide action summaries, inputs, evidence and outcomes, rather than private model reasoning. Agent tools follow proven human operations, bounded requests, cancellation and explicit capabilities.

## Current material foundation and next sequence

The in-progress G2 foundation captures original PNG bytes, immutable face material references, diffuse factors, alpha mode/cutoff, sampler wraps, UV origin and bounded source properties. BTOP v3 embeds them; geometry-only v1 and normal-bearing v2 remain compatible. OBJ/MTL import validates dependencies and refuses unsupported texture maps/transforms. GLB output uses the existing game decoder and actual renderer. A self-contained OBJ/MTL/PNG bundle preserves native material definitions and verifies derived standard views; plain OBJ refuses material loss. These are material foundations, not a completed painting system.

1. Verify/publish this foundation, independent material window, true runtime preview and material-preserving interchange. Keep topology tools in the model window and main level UI unchanged.
2. Finish G2 UV/GLB source identity, original node/pivot/material preservation, remaining selection/modeling/transforms and explicit UV editing. Do not turn the current flattened GLB inspection into an editable source.
3. Build native layer/tile/stroke schema and local undo/recovery before brush UI. Add the TP-01–14 human capabilities with real source/runtime checks and bounded memory. Preserve the full 4K/8K targets while exposing actual host limits.
4. Expose only the tested human operations through the same Editor Agent Service; add the bounded authenticated adapter at the original G11 gate. Continue G4–G12 and all original stage requirements.

Acceptance remains unproven until the relevant code, native file, runtime readback, measured checks and actual captures exist. This document and the extracted PDF alone close no implementation gate.
